# 任务

> 任务不是"要做什么"，是**"完工的定义"**。

---

## 一、配额：真正的约束不是数量

**"不超过 5 条"这种规则是错的**——它把主线任务和支线任务塞进同一个配额，而两者的时间尺度完全不同。

**真正的瓶颈不是任务多，是同一周里有几件事需要交付。**

配额改成三层：

| 项目 | 上限 | 为什么 |
|---|---|---|
| **本周必须有交付物的任务** | **≤ 3 条** | 这是唯一的硬约束 |
| 总数 | ≤ 8 条 | 宽松兜底 |
| 主线任务 | 1–2 条 | 主线本身只有 1 条；超过 2 条说明主线定义太宽 |

**其余任务可以"在跑但本周不交付"。** 那不算堆积。

---

## 二、四种类型

| 类型 | 定义 | 数量 |
|---|---|---|
| **主线** | 推进主线目标（见 [`方向.md`](方向.md) 第〇节） | 1–2 |
| **支线-产出** | 有交付物：开源、内容、作品 | 不限，但受"本周交付 ≤3"约束 |
| **支线-维护** | 不做会退化：运动、睡眠、吃饭、社交 | 不限 |
| **支线-玩** | 纯粹为了好玩，**不要求产出** | **至少 1 条** |

### 为什么要单列"支线-玩"

**因为"玩"是内在动机的来源。**

很多真正做出来的事，开始的时候都不是"任务"，是"做着玩"。

**一个没有"玩"的位置的任务系统，会被厌恶，然后停用。**

而"支线-玩"的定义是**不要求产出**。它写在清单里，只是为了让它**有位置**，不是为了给它 KPI。

## 三、时间尺度：分三张表，不要混

混在一张表里的后果：**"下个月才到期"的任务会产生"我可以等"的心理，而"本周到期"的任务被淹没。**

### 本周（≤ 7 天）

## 四、奖励：三层，从便宜到贵

### 第一层｜自动，零成本
**完工 → 进 `memory/沉淀/`。** 那个目录本身就是奖励：它是"我做过什么"的实物清单。

### 第二层｜社会反馈（最有效，而且不要钱）
**完工 → 发出去。** 被一个真实的人看到或用到，是最强的奖励，成本为零。
**这是最该用、也最容易被跳过的一层。**

### 第三层｜物质（少而准）
**只给主线节点，一年不超过 3 次。** 频率低才有效；一旦日常化就退化成折扣券。

---

## 五、不做积分 / 等级 / 徽章

**过度理由效应**：一旦给内在动机标了价，动机就变成那个价。

而且积分对成年人几乎无效：没有兑换，就只是个数字。

---

## 六、完工定义的写法

**必须是可验证的**：一个文件、一个链接、一份记录、一次发布。

- ✗ "更了解了"　✓ "一个 draft PR 链接"
- ✗ "多练练表达"　✓ "一个音频文件 + 3 个卡点"

---

## 七、过期规则

截止日过了还没做完 → **移到下面的"已过期"区，什么也不写，不解释。**

```
## 已过期
```

**不给理由，不留记录。** 自责倾向强的人，任何"失败清单"都会加速放弃。
